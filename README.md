### Особенности архитектуры

* **Оптимизация запросов (Query Optimization):** Переводит сырой и неточный вопрос пользователя в структурированный технический контекст в один абзац перед отправкой в векторный поиск.
* **Математический чанкинг:** Корректно обрабатывает математический текст, сохраняя целостность определений, координат, формул и псевдографики.
* **Стратегия скользящего контекста (Neighboring Context Retrieval):** Для предотвращения потери математического контекста система не просто извлекает релевантный чанк, а автоматически парсит его ID и добирает из базы смежные блоки данных — один чанк **до** (id-1) и один **после** (id+1). Это гарантирует, что формулы не будут оторваны от описания переменных и условий теорем.
* **Локальный стек:** Полная независимость от внешних API — использование локальной векторной базы данных и инференса моделей.
* **Интеграция с Ollama:** Использование класса RagUseCase для оркестрации запросов и генерации ответов через локальную модель deepseek-r1:14b.
